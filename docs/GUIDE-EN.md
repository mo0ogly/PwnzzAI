# JuiceLab Coach for PwnzzAI — Guide (EN)

> French version: [GUIDE-FR.md](./GUIDE-FR.md) · Technical details: [ARCHITECTURE.md](./ARCHITECTURE.md)

The **JuiceLab Coach** turns [OWASP PwnzzAI](https://github.com/OWASP/PwnzzAI)
— the deliberately vulnerable pizza shop for learning LLM security — into a
guided, remotely-tracked lab, **without modifying a single line of the OWASP
product**.

It adds four things to PwnzzAI:

1. An **automatic judge** (LLM-as-judge) that reads the student's conversation
   with the vulnerable assistant and decides whether the lab objective was
   actually reached, with a 0-100 score.
2. **Adaptive hints** generated by the local model from the student's failed
   attempts, graded over 3 levels, in FR or EN.
3. **Attack-transcript capture** in the browser, so the student (and the
   teacher) see the full exploitation flow.
4. **Reporting to the JuiceLab teacher dashboard**: a PwnzzAI lab shows up in
   the same cohort matrix as Juice Shop.

---

## 1. What gets installed

A single extra container (`pwnzzai-coach`) sits **in front of** PwnzzAI.
Nothing in the OWASP image changes.

| Container | Port | Role |
|---|---|---|
| `pwnzzai-coach` | **8095** | Student entrypoint: proxy + coach panel |
| `pwnzzai-shop` | 8090 | Raw OWASP PwnzzAI (untouched, debug) |
| `ollama` | internal | Lab model + judge/hint model |

Students use **only** `http://localhost:8095`. Port 8090 stays available to
debug PwnzzAI without the coach.

---

## 2. Prerequisites

| Tool | Detail |
|---|---|
| Docker + Docker Compose v2 | already required by PwnzzAI |
| One Ollama model pulled | for the labs **and** the judge/hints |

On arm64 (Apple Silicon, Snapdragon X1E) the PwnzzAI GHCR image is not
published: build locally (see the PwnzzAI README). The coach itself is a small
pure-Python image and builds anywhere.

## 3. Install

The stack is self-contained (PwnzzAI is cloned at a pinned commit at build
time, nothing to install alongside). From this repository root:

```bash
cp .env.example .env    # set cohort + dashboard
docker compose up -d --build
```

Then pull a model if you have not already (PwnzzAI *Basics* page, or CLI):

```bash
docker exec ollama ollama pull llama3.2:1b   # lab model
docker exec ollama ollama pull llama3.2:3b   # judge model (recommended)
```

Check everything answers:

```bash
curl -s http://localhost:8095/__coach/health
# {"ok":true,"ollama":true,"dashboard_configured":true}
```

- `ollama:true` → a judge model is available.
- `dashboard_configured:true` → reporting to the teacher dashboard is on.

## 4. Connecting to the teacher dashboard (the cohort)

Everything is set in the PwnzzAI `.env`:

| Variable | Role | Example |
|---|---|---|
| `JUICELAB_DASHBOARD_URL` | dashboard URL **as seen from the container** | `http://host.docker.internal:5000` |
| `JUICELAB_COHORT_ID` | cohort identifier | `M2-IA-2026` |
| `JUICELAB_INSTANCE_LABEL` | student machine name in the prof matrix | `pwnzzai-poste-01` |
| `COACH_JUDGE_MODEL` | Ollama judge/hint model | `llama3.2:3b` |

Important notes:

- **Dashboard on the same machine as PwnzzAI** → use
  `http://host.docker.internal:5000` (not `127.0.0.1`, which would point at the
  container itself).
- **Remote dashboard** (the teacher hosts the server) → use its IP or domain:
  `http://<teacher-ip>:5000`.
- **Leave `JUICELAB_DASHBOARD_URL` empty** → local mode: the coach works fully
  but reports nothing. Handy for solo testing.
- The dashboard **auto-registers the student** on the first event. No
  pre-enrolment needed.

After editing `.env`, recreate the coach container:

```bash
docker compose up -d pwnzzai-coach
```

## 5. For students: how it works

1. Open `http://localhost:8095` and navigate to a lab (e.g. *Direct Prompt
   Injection*).
2. A round purple **"JL"** button appears bottom-right. Click it to open the
   **coach panel**.
3. The panel shows:
   - the **lab name** and its **OWASP category** (e.g. LLM01);
   - the **objective**, in French or English (FR/EN toggle);
   - a **"captured conversation"** counter that grows with each exchange with
     the vulnerable assistant;
   - the **Hint**, **Check my success**, **View conversation** buttons;
   - a **journal** where the student explains their approach.
4. The student attacks the assistant as usual (the coach does not interfere).
5. Stuck? The **Hint** button gives advice adapted to their failed attempts
   (3 levels, from a gentle nudge to a near-complete example).
6. When they think they succeeded, **Check my success** submits the
   conversation to the judge, which replies *Solved / Partial / Not yet* + a
   score + a rationale.
7. **Teacher tip**: a URL ending in `#coach` (e.g.
   `http://localhost:8095/indirect-prompt-injection#coach`) opens the panel
   automatically — convenient to hand out to students.

Student data (token, conversations, journals, hint level) is stored in the
browser (`localStorage`, key `pwnzzai_coach_v1`) and survives reloads.

## 6. For teachers: what is reported

The coach sends the following events to the dashboard, via the same public
`POST /api/sync` contract as Juice Shop:

| Event | Trigger | Useful data |
|---|---|---|
| `session_start` | opening a lab page | path, student identity if detected |
| `hint_revealed` | clicking **Hint** | hint level |
| `challenge_solved` | judge → **Solved** | score, verdict, rationale |
| `journal_filled` | **Save** the journal | length, text |

The teacher thus sees, per cohort machine: which labs are solved, how many
hints were consumed, and the journal contents — exactly like a Juice Shop lab.

## 7. Choosing the judge model

The judge is the core of the pedagogical value. Its reliability scales
directly with model size:

| Model | Verdict | Recommendation |
|---|---|---|
| `llama3.2:1b` | **unreliable** (inconsistent verdicts) | avoid for the judge |
| `llama3.2:3b` | reliable on clear-cut cases | **minimum advised** |
| `mistral:7b` / `llama3.1:8b` | reliable on subtle cases | ideal if the machine can run it |

The judge model is independent of the lab model: you can run the labs on 1b
(fast) and the judge on 3b (reliable) on the same machine. Set via
`COACH_JUDGE_MODEL`.

## 8. Troubleshooting

| Symptom | Likely cause | Fix |
|---|---|---|
| *"Coach service unavailable"* on Hint/Check | no judge model pulled | `docker exec ollama ollama pull llama3.2:3b` |
| `health` returns `ollama:false` | same | pull a model, check `COACH_JUDGE_MODEL` |
| Inconsistent verdicts | judge model too small (1b) | move to 3b or larger |
| *"Teacher dashboard not configured"* | `JUICELAB_DASHBOARD_URL` empty | set the URL, recreate the container |
| Nothing reported despite a URL | dashboard unreachable from the container | use `host.docker.internal`, check port/firewall |
| The "JL" button does not appear | page without `</head>`/`</body>` | rare; check the browser console |
| Port 8095 already in use | another service | change the mapping in `docker-compose.coach.yml` |

Ollama DNS errors during a `pull` (`server misbehaving`): the container's
internal resolver dropped. `docker restart ollama` then retry the `pull`.

---

## 9. Why it survives OWASP updates

The proxy knows **no internal route** of PwnzzAI: it forwards everything and
only injects a `<script>` tag. Transcript capture is generic (any `fetch`/XHR
POST carrying a text field). If OWASP renames a route or restyles a page, the
coach keeps working; only `labs.json` may need a path update for lab
**detection**. See [ARCHITECTURE.md](./ARCHITECTURE.md).
